# 0002 · Bind with the foreign function API, not JNI or JNA

**Status**: Accepted

## Context

The JVM must call the four `emu-core` functions and read one struct back.

## Decision

`EmuCore` uses the foreign function and memory API (`java.lang.foreign`), final since Java 22. It looks the functions
up in the library with `SymbolLookup.libraryLookup`, makes downcall handles with `Linker.nativeLinker()`, declares the
`EmuResponse` layout field by field, and allocates each call's arguments in a confined `Arena`.

## Alternatives

**JNI**
:   Needs C glue compiled for every platform, on top of the Rust library. Two native artifacts instead of one.

**JNA**
:   No glue, but it binds by reflection at run time, is slower per call, and is one more dependency for every user.

## Consequences

- The binding is plain Scala with no native build of its own. The only native artifact is `emu-core`.
- Users need JDK 22 or later, and the test JVM needs `--enable-native-access=ALL-UNNAMED`.
- Struct offsets are declared by hand and must match `#[repr(C)] EmuResponse`. The layout is small and tested
  through every call, but a change on one side needs the same change on the other.
